# SYNONYM Jewelry — редакционная медиатека в GitHub

Статус: утверждённая схема хранения для **редизайна Next.js 16**.
Работаем **в ветке \`redesign/synonym-v02\`**, без записи в production и без изменений существующих серверных сервисов.

## 1. Чёткое разделение ответственности

- **AdvantShop** — каталог, SKU, фото конкретных товаров (включая второе фото при hover), варианты/размеры, цены, наличие, остатки, заказы.
- **GitHub → Next.js \`public/media/\`** — исключительно рекламные фото, баннеры, контент блога, видео бренда и инфлюенсеров, постеры, editorial.
- **\`src/config/synonym-media.json\`** — единая карта соответствия «блок → конкретный файл → заголовок → ссылка». Компоненты не должны содержать списки временных файлов с жёстко прописанными путями.
- Исходные продуктовые фото и SKU **не копируем** в \`public/media/\` и не размещаем в манифесте. Используем существующие компоненты ProductImage/AdvantShop.
- **Существующие \`/images/*\` работают**, пока новые материалы не утверждены и не загружены. Перемещать эти файлы без плана миграции нельзя.

## 3. Форматы и оптимизация (целевые показатели)

| Место | Desktop | Mobile | Формат и цель |
|---|---|---|---|
| Hero ×3 | 2200×1100 | 900×1200 | WebP/AVIF, лучше 300–700 КБ |
| Промокарточки ×3 | 1400×900 | 800×1100 | WebP/AVIF, лучше до 450 КБ |
| Постеры к видео | 720×1280 | тот же файл | WebP, лучше до 250 КБ |
| Видео карусели | 720×1280, 24–30 fps | тот же файл | H.264 MP4, muted autoplay, желательно до 8 МБ |
| Блог | 1200×1500 | адаптивное кадрирование | WebP/AVIF, лучше до 450 КБ |

Ограничения валидатора: **фото до 5 МБ, видео до 25 МБ**; всё свыше 1.5 МБ для фото и 8 МБ для видео дополнительно предупреждается. Это не ограничение GitHub, а наш стандарт качества. Для GitHub нежелательны тяжёлые бинарные файлы: при росте архива видео потребуется пересмотреть хранение. Git LFS по умолчанию **не используем**: обычная сборка и standalone-контейнер должны получать настоящие файлы, а не LFS-указатели.

## 4. Как заменить баннер (без изменения JSX)

1. Подготовить два файла, например \`hero-01-v01.webp\`, оптимизировать их до целевого веса.
2. Через GitHub загрузить их **в отдельную ветку**:
   \`public/media/hero/desktop/\` и \`public/media/hero/mobile/\`.
3. Открыть \`src/config/synonym-media.json\`, в \`heroSlides[0]\` заменить:
   - \`desktopSrc\` на \`/media/hero/desktop/hero-01-v01.webp\`;
   - \`mobileSrc\` на \`/media/hero/mobile/hero-01-v01.webp\`.
4. При необходимости изменить \`objectPosition\`, \`alt\`, рекламный заголовок, CTA и URL перехода.
5. Сделать commit в \`redesign/synonym-v02\`; дождаться GitHub Actions; оценить скриншоты 390 и 1440 px.
6. После утверждения — отдельный релиз, **не автоматическая публикация** на магазин.

Если загружено только desktop-изображение, оставьте \`mobileSrc: null\`: компонент использует один файл на всех устройствах. Когда утверждена отдельная мобильная композиция — замените значение на путь к мобильной версии. Для новых изображений в \`public/media\` имена обязательны в lowercase ASCII и с \`-v01\`, \`-v02\` и т.д. Не перезаписывать прежнее имя: статические файлы \`/media\` кешируются как immutable.

## 5. Схема манифеста

- \`heroSlides[]\`: \`id\`, \`eyebrow\`, \`heading\`, \`desktopSrc\`, \`mobileSrc\`, \`alt\`, \`href\`, \`cta\`, \`objectPosition\`;
- \`promotions[]\`: \`id\`, \`src\`, \`mobileSrc\`, \`alt\`, \`title\`, \`cta\`, \`href\`;
- \`brandVideos[]\`: \`id\`, \`video\`, \`poster\`, \`label\`, \`kind\`, \`productSlug\`;
- \`blogCovers[]\`: \`id\`, \`href\`, \`src\`, \`alt\`, \`title\`.

**Три Hero, три промокарточки и четыре обложки блога** — утверждённая текущая структура. Фото четырёх категорий в блоке 02 не меняем, т.к. это ранее согласованное требование.

## 6. Видео / инфлюенсеры

Пока роликов инфлюенсеров нет, используются demo-файлы из \`/images\`, помеченные \`kind: "brand-demo"\`. Не показываем несуществующие отзывы, имена, согласия или оценки. Видео запускается без звука, только центральный видимый ролик; offscreen и скрытая вкладка — пауза. При \`prefers-reduced-motion\` остаётся ручное воспроизведение.

Когда ролик будет предоставлен, сначала проверить согласие на использование образа и видео, срок/территорию лицензии и соответствие фактически показанного изделия. Затем загрузить MP4 и постер и только после подтверждения прописать \`kind: "influencer-approved"\` и неперсональный \`approvalRef\` (ссылка на внутренний тикет или номер акта, **не секретный документ**). Если нужна привязка товара, \`productSlug\` должен ссылаться на реальный товар AdvantShop; отсутствие связи — \`null\`.

Автовоспроизведение зависит от браузера/режима энергосбережения; ручное управление и постер обязательны.

## 7. Приватность, лицензии, кеширование и релиз

- Любой файл в \`public/\` доступен публично после деплоя, даже если репозиторий приватный.
- Никаких API-ключей, токенов, личных документов, неопубликованных договоров.
- Использовать только изображения и видео, права на которые у SYNONYM есть; не переносить фото Missoma.
- Не хранить несжатые master-версии (PSD/AI/гигантские MOV) в Git-репозитории; подготовленные web-версии — да.
- **Замена контента требует commit + сборку/деплой**, GitHub здесь не CMS и не позволяет мгновенно менять баннеры через обычную админку.
- \`Cache-Control: immutable\` для \`/media/*\` означает: при обновлении создавать \`-v02\`, менять путь в манифесте; старые файлы удалять отдельным проверенным коммитом.
- Проверка: \`npm run media:check\`, \`npx tsc --noEmit\`, \`npx eslint src/components/redesign src/app/redesign-preview\`, \`npm run build\`, браузерный QA по скриншотам.
- Включение в рабочий сайт допускается только после согласования; никакой автоматической записи в \`main\`.

## 8. Пока не реализовано

- Новые рекламные файлы не созданы и не загружены; манифест ссылается на **существующие временные изображения/видео**, чтобы сайт не ломался.
- Не подключены реальные ролики инфлюенсеров.
- Это не замена фотогалереи конкретного товара: она по-прежнему подключается к AdvantShop.
